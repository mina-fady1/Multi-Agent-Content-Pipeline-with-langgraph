**Pipeline audit — 21 October 2026**

The pipeline's basic graph works, but its acceptance status and research audit trail are not reliable enough for unattended publication. The most urgent defects are automatic acceptance of invalid reviewer responses and the substitution of static fixtures for unsuccessful live research. There are also confirmed input-validation, export, configuration, and response-handling bugs.

This was a review of the current local files, not a Git diff: this workspace has no Git repository. The review covered both CLIs, all 21 project Python files, policy/configuration files, and the existing `output/week-42` artifacts. Source files and existing outputs were not modified. Reproductions used mocked model/search responses and temporary directories; no Gemini, Tavily, or Ollama requests were made. Public Google documentation was consulted to verify pricing. Live provider availability, rate limits, and the factual accuracy of every generated claim were not established by this audit.

Severity means practical impact: **High** can invalidate acceptance or evidence guarantees; **Medium** causes incorrect behavior under a concrete supported or malformed input; **Low** covers narrower checks and presentation defects.

**High — An invalid reviewer response becomes an approval.** In [reviewer_agent.py](<D:/programming mina fady/Multi-Agent Content Pipeline with langgraph/agents/reviewer_agent.py:112>), a parsing or schema error returns `ACCEPT`, score `8.5`, unless the raw response contains `REJECT`. Offline calls with an empty string, `Service unavailable`, `null`, `[]`, and an invalid numeric score all reproduced acceptance. Consequently, a draft that passes mechanical checks can reach the accepted-content exports without a valid editorial verdict. Return a failed review for invalid output, validate against the schema, and retry the review within a bounded policy. Never manufacture an approval from a parsing failure.

**High — Failed live research is recorded as successful retrieval.** In [web_search.py](<D:/programming mina fady/Multi-Agent Content Pipeline with langgraph/skills/web_search.py:100>), a Tavily exception, zero usable results, or absent API key triggers static fixtures. Their text ignores the query, their URLs enter the retrieved-URL set, and the log reports successful retrieval without recording fixture provenance or the failure. Mocking both zero results and an exception returned two pentesting fixtures and logged `Retrieved 2 domain-filtered items.` Offline fixtures are documented, but this also happens after a live-search failure. Use an explicit demo mode, label fixture provenance, and fail live research honestly when no evidence is available. This finding does not establish that the saved weekly run used fixtures or that a particular fixture URL is nonexistent.

Run isolation and artifact handling need the following corrections:

| Severity | Finding and evidence | Recommended correction |

| Medium | **Research state survives across runs in the same process.** Global [query logs and retrieved URLs](<D:/programming mina fady/Multi-Agent Content Pipeline with langgraph/skills/web_search.py:20>) and [used KB IDs](<D:/programming mina fady/Multi-Agent Content Pipeline with langgraph/agents/research_agent.py:18>) are not reset by [run_week](<D:/programming mina fady/Multi-Agent Content Pipeline with langgraph/agents/orchestrator.py:94>). Two offline weekly runs showed the second exporting the first run's query, accepting its old URL, and selecting the next KB finding. | Medium | **Slot IDs can write outside the chosen output directory.** IDs are used directly in [image paths](<D:/programming mina fady/Multi-Agent Content Pipeline with langgraph/agents/visual_agent.py:21>) and [per-post JSON paths](<D:/programming mina fady/Multi-Agent Content Pipeline with langgraph/agents/orchestrator.py:252>). An accepted ID `../../victim` wrote PNG and JSON files outside the requested output directory in an isolated temporary-directory reproduction. Existing files at those destinations could be overwritten. This requires control of a weekly plan or programmatically supplied slot; the single-piece CLI uses a fixed ID. | Restrict IDs to safe filename characters, reject absolute paths and separators, and verify each resolved destination stays inside its intended directory. |
| Medium | **Duplicate IDs silently lose one piece and duplicate another.** [load_plan](<D:/programming mina fady/Multi-Agent Content Pipeline with langgraph/agents/orchestrator.py:50>) does not check uniqueness. The later [slot map](<D:/programming mina fady/Multi-Agent Content Pipeline with langgraph/agents/orchestrator.py:127>) overwrites duplicate keys. | Medium | **Revisions erase the evidence of the initial rejection.** The retry mutates the same slot, and [artifact export](<D:/programming mina fady/Multi-Agent Content Pipeline with langgraph/agents/orchestrator.py:184>) saves only the final draft and review. A reject-then-accept run preserved `retry_count=1`, but neither the original draft nor its rejection feedback. Code-quality metrics in graph state are also not exported. | Store an append-only attempt history with raw/processed drafts, code-gate results, review verdicts, feedback, and timestamps. |
| Medium | **Reusing an output directory leaves old individual posts available.** [Per-post export](<D:/programming mina fady/Multi-Agent Content Pipeline with langgraph/agents/orchestrator.py:228>) writes accepted posts without removing obsolete artifacts. After exporting an accepted slot and then a dropped version, `final_content.json` was empty but `posts/stale.json` still contained the old accepted text. Images are likewise not reconciled. | Use a fresh directory per run, or atomically publish an authoritative manifest and remove only obsolete generated files. Consumers should use the current manifest rather than scan stale directories. |

The recommended implementation order is: first reject invalid reviews and separate fixture mode from live research; next fix source validation and connect the actual policies to prompts; then validate plans and isolate run state; then preserve revision history and reconcile exports; finally address model selection, content blocks, pricing, and the narrower quality checks. Add regression tests around the confirmed reproductions before relying on acceptance status for unattended publication.
